## Scenario and fix

**R5-N1.** The SignalRGB entry in NeedsList is `check = { path = 'SignalRGBPath', auto = { reg = 'mRegSignalRGB' } }`. The default is `SignalRGBPath=auto`, so the check falls to `reg`. `Needs.rainmeterEnv.reg` does `skin:GetMeasure('mRegSignalRGB')`. That measure was added to `Settings/Chrome.inc` only; the SignalRGB skin names the same registry read `mProtocol`. `GetMeasure` returns nil, `reg` returns `''`, the mandatory launcher need fails, `SignalRGBNeedBlocked=1`, and `mBlocked` sets `SelfHidden=1`: the skin disappears for everyone who has not typed a path, whether or not SignalRGB is installed. Tests passed because they fake the registry by measure name. Fix (done): rename `[mProtocol]` to `[mRegSignalRGB]` in SignalRGB.ini and update the one reader in SignalRGB.lua. Same measure name now exists in the skin and the Settings windows. A test that loads the real ini and checks that every `reg =` name in NeedsList is defined in the skin that owns it would have caught it (lint worker).

**R5-N2.** Core.inc is included from `[Variables]`, so `[mCore]` comes before the skin's own measures. At `Initialize()` a later measure does not exist (`GetMeasure` nil), and any Registry measure returns `''` until its first update. The first check therefore reads "launcher missing" even where it is installed, and the next check is 60 s away. Fix (done): the load check and the first two updates (about 5 s apart) always run; in the first two, if a registry read came back empty, `NeedState`/`NeedBlocked` are left at their defaults (not blocked), and the third check applies the real answer. Cost: a genuinely missing SignalRGB stays visible for about 5 s after load. New test in `test_core.py` (`registry not ready at load`, `still empty after warm-up`, `registry answers`).

**R5-N3.** Helpers.txt `fan-tasks` args were `-ArgumentList '-NoProfile','-ExecutionPolicy','Bypass','-File','{ROOT}tools\fan-tasks.ps1'`. Windows PowerShell 5.1 joins array elements with spaces and does not quote them, so a profile folder with a space (`<drive>:\Jane Doe\...`) gives `-File <drive>:\Jane` and the elevated window fails; `<drive>:\O'Neil\...` ends the single-quoted string early (a syntax error, or code if the folder name is crafted). The failure is safe (nothing wrong runs, the row reports NOT FOUND AFTER THE RUN), but the feature does not work for a large share of Windows profile names. Fix (done): one double-quoted argument string with the path in escaped quotes: `-ArgumentList \"-NoProfile -ExecutionPolicy Bypass -File `\"{ROOT}tools\fan-tasks.ps1`\"\"`. Apostrophes are harmless in a double-quoted PowerShell string; a `$` or backtick in the folder name would still be interpreted (own folder, own risk, very rare). Only `{ROOT}` is used because lint forbids other placeholders. Test added (`fan-tasks path is double-quoted`). [PC] to confirm that the elevated window really receives the path.

**R5-N4.** Rainmeter reads an option as a formula only when it starts with `(`. `Disabled=Max(1-#SignalRGBHasApi#,#ApiOff#)` is parsed as text and means 0. The Lua also disables the measure for `SignalRGBApi=0`, and `HasApi` is `assume` (always 1), so nothing is visible today, but the documented gate does nothing. Fix (done): `Disabled=(Max(...))`.

**R5-N5.** `fan-tasks.ps1` registers tasks through the Task Scheduler. A standard (or UAC-filtered) token may not be allowed to open files in `C:\Windows\System32\Tasks`; if not, `io.open` fails like a missing file, `FanControlHasTasks=0`, MAX falls back to launching Fan Control with a UAC prompt, and `FanControlHasSensors=0` hides the live fan value although everything is installed. Cannot be checked here. Fix (done, mitigation): either the task file or `%ProgramData%\ControlPlaine\FanControl\FanControlSensors.ps1` (left by fan-tasks.ps1 in a folder with Users = ReadAndExecute) now counts. Remaining gap: pwsh missing (no copy) and tasks unreadable. Better fix for the script owner: have fan-tasks.ps1 write a small `tasks.ok` marker into that same folder at the end.

**R5-N6.** `PlaynitePath`, `DeepCoolPath`, `FanControlPath`, `ControllersWheelApp` and PATH entries are opened with `io.open` every 60 s in every skin and every 2 s while the onboarding is open. A path on a NAS or mapped network location that is offline can block for tens of seconds each time and freezes all skins (Rainmeter runs scripts on the UI thread). Fix (done): paths starting with `\\` are not opened (a program path counts as present, a PATH entry is skipped). Drive letters mapped to network shares are still opened (cannot be told apart cheaply). Test added.

**R5-N7.** `Add-Content -Encoding ascii` on a State.inc that Rainmeter saved as UTF-16 appends single-byte text to a two-byte file; and without a line break at the end of the file the key lands on the previous line. Fix (done): append in the file's own encoding (BOM check) after `` `r`n ``. A blank line in State.inc is harmless.

**R5-N8, R5-N9.** Fixed as described in the table. R5-N8 matters only when code starts using `required_for`; `optional_for` is documented in the file header. Test added.

**R5-N10.** `Settings.lua` opens the onboarding whenever State.inc lacks `SetupDone=1`. Only `install.ps1` writes `SetupDone=1` for an existing profile. The documented update path for the live PC is `git pull --ff-only` and a refresh, not a re-run of the installer, so the owner's own PC (and every existing user) gets the full first-run flow the first time Settings opens. It is skippable (SKIP SETUP), but clicking NEXT through the SKINS step switches off every skin whose mandatory need is not found, including a skin the user already runs with a non-default setup that the check cannot see. Fix options: (a) treat "State.inc or User.inc already exists and has at least one key" as an existing profile in `Settings.lua` and write `SetupDone=1`; (b) say in the release notes that existing users run SKIP SETUP; (c) add a one-line pull hook. Not changed: it is a product decision and touches the first-run contract (a fresh install also has both files, created empty by install.ps1, so a content test is needed).

**R5-N11.** Rainmeter's `SKIN:Bang` joins its arguments into one bang string; whether it adds quotes around each is exactly the open gate R1-S3. `Onboarding.lua` sends `Parameter` values and clipboard text such as `-NoProfile -ExecutionPolicy Bypass -File "C:\...\MediaPlayer.ps1"` this way. If the arguments are split on spaces, `!SetOption mRun Parameter` receives only the first word, so RUN IT FOR ME starts `powershell.exe -NoProfile` hidden; with no script it waits on stdin until the 600 s timeout while the button shows RUNNING. COPY COMMAND would put a truncated string on the clipboard. Nothing unsafe runs (the program and the first word come from the allow-list), so medium. Fix after the PC check: wrap the argument in quotes and escape inner quotes the way Rainmeter documents, or set `Parameter` through a variable (`!SetVariable OnbArgs ...` and `Parameter=#OnbArgs#`). Also lower `Timeout` of `mRun` to a few minutes.

**R5-N12.** The `fan-tasks` helper starts `powershell.exe -Verb RunAs` on `<repo>\tools\fan-tasks.ps1`. R3 moved the elevated sensor reader to ProgramData, but this one-off installer script is still read from the user-writable repo at the moment of consent; the UAC prompt shows "Windows PowerShell", not the script. Any process running as the user could edit the script between the click and the prompt. Same trust class as running any repo script as admin; it needs the user to click and to accept UAC. Fix options: show the script path in the SOURCE line (already shown) and add to `docs/guide/first-time-setup.md` that the UAC prompt belongs to the Fan Control tasks; or copy the script to ProgramData first (needs an elevated step anyway). Left as accepted risk.

**R5-N13.** Four skins use `IfConditionMode=1` on `mBlocked`, so each update (1 s) re-runs `[!SetVariable SelfHidden n][!UpdateMeasure mVisible]`. `mVisible` only acts on a change, so the cost is tiny (two bangs per second per skin, 4 skins), and mode 0 would also fire on change. Remove `IfConditionMode=1` (Playnite, DeepCool, FanControl, SignalRGB) unless a reason is written beside it. Note the skin-level `SelfHidden` is shared: every `mBlocked` false branch writes `SelfHidden=0`, which would override any other reason to hide; today only Media and Controllers set it from elsewhere and they handle it.

**R5-N14.** `ControllersHasDsx` gates the click and tooltip of DualSense rows only. Text fix in NeedsList, or gate the battery row.

**R5-N15.** `Placement.stack` starts a new column when the next skin runs below the work area; with a 1080 x 1920 portrait screen and Scale 1.5 the third column may start beyond the screen width. Clamp `x` to the work area or stop at the last column that fits and warn in the PLACEMENT note.

**R5-N16.** `Initialize()` opens Onboarding and returns, leaving the General window loaded behind it; after FINISH the General page appears (probably wanted: "Settings opens once, then you are in Settings"). [PC] to confirm there is no flicker of two windows and that SKIP SETUP lands somewhere sensible.

**R5-N17, R5-N18, R5-N19.** As in the table. R5-N17: the audio and recycle plugins ship with Rainmeter, so `bundled` is correct, but two gate paths are dead code. R5-N18: for the owner of Power.lua, see the open R2-N1/N2 gate. R5-N19: report to the layout owner.

## Checked and clean

- **Command execution.** The only places that start a program from the onboarding: `Run()` (program and arguments from `Helpers.txt`, selected item must be failing, one at a time, command shown first, `Copy()` runs nothing) and `install.ps1` (entries with `installer=1` only, never the elevated one). No user text reaches a shell: item keys, skin names and `SkinOn`/`EditPath` strings are constants from NeedsList and the SKINS list, built with `string.format('%s')` into fixed templates. `!Move` receives numbers and fixed names. Detection (`Needs.lua`) opens files and reads variables and registry measures only.
- **Writes.** Onboarding writes only to `State.inc` (`OnbStep`, `OnbOnly`, `OnbPre`, `OnbSkip`, `OnbSel`, `OnbPage`, `OnbScreen`, `OnbEdge`, `OnbPlaced`, `SetupDone`) and, through Settings.lua `SkinOn`/`Set`/`EditPath`, `User.inc` and `Rainmeter.ini`. `install.ps1` creates `User.inc`/`State.inc` only if absent and appends `SetupDone=1` only if absent.
- **UAC and elevation.** Exactly one helper is `elevated=1`; the skin never hides Windows' prompt, shows "Windows will ask for admin permission (UAC)", and the installer skips it (`installer=0`). No helper edits the registry or system folders; MediaPlayer.dll and IsFullScreen.dll go to the user's own `%APPDATA%\Rainmeter\Plugins`. (Download integrity of MediaPlayer.dll is R4-T2, still open.)
- **Defaults and failure modes.** Every flag defaults to "present" in the skins' `Defaults.inc` (`HasX=1`, `NeedBlocked=0`). If `Needs.lua`/`NeedsList.lua` fail to load, a skin has no entry, `GetMeasure` is nil, or anything throws, `Core.lua` leaves the defaults (pcall around the whole evaluation; tested: missing lists, broken list, unknown skin). A Controllers state with `blocked` shows nothing and runs nothing.
- **Efficiency.** Per skin, one 60 s check: 1 to 5 `io.open` calls (WiFi up to about 35 because of the PATH scan for speedtest.exe), no process, no redraw unless a flag changes. `Needs.lua` and `NeedsList.lua` are read once per skin load (26 reads for 13 skins), not per check. `Core.lua` already skips `!SetVariable` when a value is unchanged. Settings re-checks once a minute and on a change (18 small file reads per change). Onboarding polls every 2 s only while its window is open and redraws only when the loaded-skin list or the missing-item list changes.
- **Controllers overlay.** `RowNHit` keeps `MouseOverAction` so hover still reveals; `RowNClick` carries the click, tooltip and cursor and is hidden by the `Hidden=(...)` formula (`sHit` has `DynamicVariables=1`). `target()` also returns an empty target when the flag is 0, so a stale overlay cannot start anything. Check the visual behaviour on the PC.
- **State machine (Onboarding).** `stepIndex` falls back to step 1 on an unknown `OnbStep`; fix mode shows only SETUP and DONE ends it; `Finish`/`SkipSetup` both write `SetupDone=1` and clear the progress keys; `Back`, `GoIndex` and `Next` cannot leave the list; `OnbPre` makes the "turn off blocked skins" step run once; `asking`, `running` and `copied` are in-memory and reset by `Select`/`goStep`/`RunDone`. `PlaceScreen` cycles screens with `n % #list + 1`; `Place.screens` always returns at least one screen, so the string formats cannot index nil.
- **install.ps1.** Helper list parsed with the same rules as the Lua parser; `Test-Helper` handles `file:` and `path:` and expands `%ENV%`; missing program is reported, not fatal; layout backups use a timestamp with seconds, existing layout kept before overwrite (R4-T3 closed); `Select-String` on `SetupDone=` handles a BOM file.
- **Lint and tests** (after the fixes): 0 lint problems; `test_core`, `test_onboarding`, `test_onboarding_flow`, `test_placement`, `test_controllers_gating` and the rest: 0 failures.
